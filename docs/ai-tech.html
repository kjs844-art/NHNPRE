1. 사용한 AI 도구

도구용도
Claude (Anthropic) — Claude Code 기획 문서 작성, 전체 코드 구현(TypeScript/React/Phaser), 절차적 아트(코드 드로잉)·사운드(WebAudio 합성) 생성, 스토리·대사 집필, Playwright 자동 플레이테스트 작성·실행, 버그 수정, 배포 설정, 본 문서 작성
Claude 멀티에이전트 워크플로우 ① 디자인 비평 패널: 독립된 AI 에이전트 3개가 각각 다른 심사 관점으로 기획서를 비판 → 설계 반영
② 코드 리뷰: AI 에이전트 3개가 관점별로 결함을 탐색하고, 발견된 각 항목을 별도의 '반박 전담' AI가 적대적으로 검증

이미지 생성 AI·음원 생성 AI는 사용하지 않았다. 모든 시각 요소는 Phaser Graphics 코드 드로잉, 모든 소리는 WebAudio 오실레이터/노이즈 합성으로 제작했다 (외부 에셋 0개).

2. 개발 구조 — 사람은 디렉터, AI는 제작 전 공정

[사람·디렉터]  방향 결정 (장르: 심리 호러 + 소름 반전 / 브라우저 즉시 플레이 / 개인 참가)
      │
      ▼
[AI]  ① 기획: 디자인 문서 초안 (컨셉·코어루프·반전 설계·수치 초안)
      ② 비평: AI 3인 심사 패널 — "첫 60초 재미" / "구현 리스크" / "반전 완성도"
              → 치명 결함 6건, 중요 결함 12건 도출 → 설계 수정
      ③ 구현: 엔진(순수 TS 상태머신) → 방 드로잉 → React UI → 오디오 합성
      ④ 검증: Playwright로 5일 밤 전체 자동 완주 + 배드엔딩 경로 검증 (콘솔 에러 0)
              → 밸런스 결함 발견("배드엔딩 도달 불가") → 수치 재설계 → 재검증
      ⑤ 리뷰: AI 결함 탐색 3방향 + 항목별 적대적 반박 검증 → 확정 결함만 수정
      ⑥ 산출: GitHub Pages 배포 설정, 플레이 영상 녹화, 제출 문서

커밋 기록(github.com/kjs844-art/NHNPRE)에 위 과정이 단계별로 그대로 남아 있다.

3. AI에게 준 주요 프롬프트·지시 사항

3-1. 방향 지시 (사람 → AI)

"추리 및 스릴러물. 약간 공포스럽고 스릴도 있으면서 반전이 엄청나고 그 반전이 소름끼치게 만들었으면 한다."
"play in browser로 실행되는 게임이어야 한다. 요건에 충족하는 게임을 처음부터 끝까지 만들어서 배포와 제출 직전까지."

3-2. 디자인 비평 패널 프롬프트 (AI → AI, 요약)

"당신은 게임 해커톤 심사위원입니다. 심사자는 3~10분만 플레이합니다. '첫 60초 안에 재미와 긴장감이 전달되는가' 관점에서만 비판하세요. 온보딩 속도, 첫 이상 현상까지의 시간, 조작 이해 난이도를 점검하고 구체적 수정안을 제시하세요."
"당신은 시니어 게임 프로그래머입니다. 판정 애매함(플레이어가 '물체 이동'을 실제로 알아챌 수 있는 시각 대비인가), 상태머신 엣지케이스(보고 모달 중 스폰, 카메라 전환 중 판정), 밤 길이와 스폰 수의 수치 균형을 비판하세요."
"당신은 호러 내러티브 디자이너입니다. 반전의 복선이 충분한가, 논리적으로 성립하는가, CAM 07 연출이 실제로 소름을 유발할까를 비판하고 더 소름끼치게 만들 수정안을 제시하세요."

이 비평에서 나온 핵심 수정: 스크립트된 오프닝(첫 이상 T+10초 고정), 관찰한 방에만 비교형 이상 스폰(기억 기준선 보장), 이동↔소실 상호 정답 인정, "화면 속 인물은 안 볼 때만 움직인다"는 반전 연출, 근무자 이름 등록 → 최종 보고서에 자기 이름 출력, 7번째 보고 선택지 [실종자].

3-3. 코드 리뷰 워크플로우 프롬프트 (AI → AI, 요약)

"실제 코드를 읽고 검증 가능한 결함만 보고하라. 스타일 지적 금지." (탐색 3방향: 상태머신/생명주기 · 엔진 로직 · 렌더/UX) → 각 발견 항목마다: "다음 버그 보고를 반박하라. 재현 가능한 결함인지 판정하라. 확신이 없으면 real=false."

4. 게임 내 알고리즘형 AI — 'AI 디렉터'

게임 안에는 플레이어 실력에 실시간 적응하는 결정론적 디렉터 시스템이 동작한다 (src/game/engine/director.ts).

입력 신호출력 제어
최근 8회 판정 이력(적중/오탐)
평균 탐지 소요 시간
현재 침식도		 · 스폰 간격 배율 (숙련 0.7× ~ 고전 1.35×)
· 유형 가중치 — 숙련자에겐 미묘한 변화(이동·소실), 고전 중이면 명확한 변화(침입자·조명)
· 동시 발생 상한 (밤 진행도 × 실력 비례)
· 자비 규칙: 침식도 70% 초과 시 스폰 지연 + 에스컬레이션 감속

모든 판정은 시드 가능한 RNG(mulberry32) 위에서 동작해 자동 테스트로 재현·검증했다.

6. AI 산출물 검증 방식

  • tsc 타입체크 + oxlint 정적 분석: 경고 0
  • 밤 엔진 단위 테스트 19개(node:test): 시드 RNG 결정성, AI 디렉터 적응·자비 규칙, 보고 판정(적중/near-miss/오탐/관용 규칙), 방치→배드엔딩·즉시처리→클리어를 결정론적으로 검증
  • Playwright 자동 플레이테스트: 5일 밤 전체 완주(반전·트루엔딩 포함), 배드엔딩·재시도 경로, 브라우저 콘솔 에러 0건 확인
  • 프로덕션 빌드를 GitHub Pages 실제 경로(/NHNPRE/)로 서빙해 부팅·플레이·자산 로드(404 0) 확인
  • 밸런스 계측: 방치 시 침식도 궤적을 초 단위로 로깅해 "배드엔딩 도달 불가" 결함을 발견·수정
  • 프로덕션 빌드(vite build) 및 GitHub Pages 경로 검증
